## 0. Constraints this roadmap is built around

| Constraint | What it means in practice |
| --- | --- |
| **Shared local DB is read-only** (`docs/ISSUES.md` ground rules) | `SELECT`s to check state only. No `migration up`, no `db reset`, no test data, no scratch DB inside the shared cluster (`scripts/db-scratch.sh` refuses without `ALLOW_SHARED_CLUSTER=1`) |
| **SQL is tested only in throwaway containers** | `scripts/pg17-isolated.sh` with a **unique** `PG17_NAME`. The default name is derived from the worktree directory, and two worktrees are both called `elm`, so `eventmap_pg17_elm` already exists and is not ours. Use e.g. `PG17_NAME=planb_$(date +%s)` and destroy it afterwards |
| **New migrations are prepared, not applied** | They go in `supabase/prepared/<date>_<topic>/` with a README holding the runbook, the validation table, the rollback and the client follow-up. The owner moves them into `supabase/migrations/` and applies them |
| **New migration versions must sort after `20261120100000`** | Then a plain `migration up --local` applies them. Anything older needs `--include-all` (series reviews already does) |
| **Always `--local`** | This worktree is `supabase link`ed to a hosted project, and `supabase migration list` defaults to `--linked` |
| **Client/schema policy** (`docs/ISSUES.md`) | The client targets applied migrations. A probe-and-fallback is allowed only where a missing object changes *what is shown*, never *what is written* |
| **Sibling worktrees share the DB** | Two are at `a5ba608`. Anything that changes an existing constraint or signature can break them (that is why series reviews is held) |

What this means for ordering: **anything that needs only the client, or an
object that is already applied, can be done and finished end-to-end now.**
Anything that needs a new migration can be built and validated in isolation,
but it is "done" only after the owner applies it. That work therefore goes
later and is sized so the client never depends on it.
